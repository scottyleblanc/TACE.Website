The nine layers of the ai development stack, when each one acts on a change, and the file, script or setting that backs it. Each layer is shown twice: as built in TACE.Oracle.Admin, and as the reusable form in powershell-gate-kit.

where each layer acts on a change

A change moves left to right. Layers 1, 2 and 7 shape it before and while it is written. Layers 3, 4, 5 and 8 are checks. Layer 6 runs those checks at the push and blocks the merge in CI. Layer 9 turns anything that still gets through into a new check.

how the pieces connect

One source for the rules

The standards in Docs/standards/ are both what the gate enforces and what AGENTS.md is built from, so the agent and the gate read the same rules.

One gate, run twice

The pre-push hook and CI both call Invoke-Gate.ps1. A check that fails on the laptop fails the same way on the pull request. The kit lets a repository's hook skip its slow checks with -Quick; CI still runs every check.

Records the gate reads

Some work cannot run in CI: the model review and the integration tests. Each writes a committed record, LastReview.json and LastRun.json, and the gate checks the record is current for the branch.

Tests prove the invariants

Each invariant cites the test that proves it. The mutation script breaks the invariant and confirms that test fails, so a passing test means something.

The merge is the hard stop

The GitHub ruleset makes the gate a required check. Until every check passes, the change cannot reach master, whoever or whatever wrote it.

The kit is the reusable copy

powershell-gate-kit holds layers 2 to 8 in a form any PowerShell repository takes as a subtree at tools/gate/, configured by one gate.config.psd1, at its root or in Gate/. Layers 1 and 9 stay with TACE.Oracle.Admin.
